# Lodum Roadmap

This document outlines the planned future enhancements for `lodum`. Our goal is to maintain the library's high performance while expanding its utility in the Python ecosystem.

## 1. Short-Term Goals (v0.2.0 - v0.3.0)

### Streaming Support

* **Goal**: Enable processing of datasets larger than memory.
* **Implementation**: Add `dump_stream(obj, stream)` and `load_stream(cls, stream)` to the IDumper/ILoader protocols.
* **Target Formats**: JSON (via `ijson` or similar), MsgPack, CBOR.

### Partial Serialization

* **Goal**: Allow users to serialize only a subset of fields or only fields that have changed.
* **API Idea**: `dumps(obj, include={'id', 'name'})` or `field(serialize_if_changed=True)`.

### Framework Integrations

* **FastAPI**: Create a `LodumResponse` class and a `Depends` provider for automatic parsing.
* **Django**: Implement a custom Model Serializer/Renderer for Django REST Framework.

## 2. Medium-Term Goals (v0.5.0+)

### Advanced Schema Features

* **Schema-to-Code**: A CLI tool to generate `@lodum` classes from an existing JSON Schema.
* **OpenAPI Support**: Utilities to convert `lodum` schemas directly into OpenAPI/Swagger specifications.

### Compression Utilities

* **Goal**: Native support for transarent compression.
* **API Idea**: `dumps(obj, compression='gzip')` returning compressed bytes.

## 3. Long-Term Vision (v1.0.0)

### Compiler Enhancements

* **Goal**: Explore compiling the generated bytecode handlers into C via Cython or MyPyC for even greater speed.
* **Zero-Copy**: Investigate deeper integration with Python's buffer protocol to reduce memory copying for large binary payloads.

### Ecosystem

* **IDE Plugin**: A VS Code / PyCharm plugin to auto-generate `field()` definitions and validate schema compliance in real-time.
